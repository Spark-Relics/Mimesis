# 完整产品研发与验收

更新：2026-09-11。此文是后续研发的范围与完成标准，不表示全部能力已实现。

## 产品边界

Mimesis 是运行在用户电脑上的企业级可编排采集网关。用户通过原生浏览器、录制、脚本和可选 Agent 建立可复用流程；业务系统调用固定版本，获得经过校验的数据和明确的失败原因。目标覆盖多种页面与接口模式，不承诺无需配置即可采集任意网站。

“便携”必须落到：可选择的数据目录、相对产物索引、依赖自包含、启动前环境检查、可验证的导入导出、备份恢复和版本升级。换机器时凭据与系统加密绑定如何处理必须明确，不能只复制 Cookie 文件就声称环境完整迁移。Electron Session 隔离不等于操作系统机器码隔离。

“企业级”必须落到：任务与数据一致性、可追踪版本、可解释的恢复行为、资源配额、账号与租约隔离、交付幂等、运行证据、凭据保护、备份、长时间运行及故障注入验收。

## 设计与扩展原则

1. **设计先于交互实现。** 先列清用户任务和所有状态，再生成设计稿与必要素材，再建立真实组件并截图验收。采用顶部导航和单列工作区，不恢复侧栏后台布局。视觉与交互必须符合既定 V3 方向。
2. **一个领域入口。** 桌面、API、Agent 都调用同一套版本发布、任务、环境和数据服务。界面只负责表达状态，不自行推断任务成功。
3. **一个状态权威。** 每个实体明确持久化归属；缓存、UI 状态和事件不是第二个数据库。状态变更与事件/outbox 在同一事务提交。
4. **依赖向内。** contracts → SDK → 执行核心；BrowserHost、存储和模型适配属于外层。网关不控制 WebContents，渲染进程不导入特权模块。依赖图由自动检查约束。
5. **扩展有依据。** 先验证真实场景，再抽取端口。只在具体扩展能力进入开发时建立模块，避免空壳插件系统与重复抽象。
6. **明确副作用。** 失败重试、检查点和恢复必须区分可重放操作与不可重放操作。交付失败不能重新采集；取消不能宣称撤销已经发生的网页行为。
7. **移除替代实现。** 新路径验收后删除旧入口、旧协议、重复样式和无调用模块；历史数据由独立迁移处理并保留备份。

## 依赖顺序

不删减上述范围，按能被真实验证的纵向功能分批完成：

1. **统一底座**：清除伪功能遗留、规范依赖、领域拆分、事务存储与数据迁移、产物索引和文件配额。
2. **完整编排**：版本模型、递归但有界的流程解释器、脚本能力代理、调试/断点和运行证据；桌面和 API 调用同一发布版本。
3. **采集与数据能力**：网络请求/响应、复杂页面、列表详情循环、数据 Schema、清洗管道、增量采集和可靠交付。
4. **生产资源管理**：账号、代理、密钥、环境租约、并发配额、恢复与定时调度。
5. **Agent 闭环**：复用前述观察/执行端口，生成或修复候选流程，显示差异，经过验证后发布；禁止静默修改生产版本。
6. **便携发行与综合验收**：覆盖全流程的设计审查、干净机器安装/迁移、更新回滚、故障注入、压力与持续运行。

每批提交须同时覆盖正常路径与相关失败路径，不以“接口已写”“页面已有”“效果图已画”标记模块完成。已有架构提案用于背景参考，冲突时以本文件、当前契约和用户指令为准。

## 关键技术决策进入实现前必须验证

- SQLite 在 Electron/Node 中的运行兼容性、事务边界与非阻塞访问方式；不能把现有整个 JSON 当作一行 BLOB 就称为事务架构完成。
- 受限脚本的进程/运行时隔离、终止能力和权限代理。Node vm 本身不作为不可信代码安全沙盒。
- 浏览器控制权、取消后的操作清理、租约 fencing 与人工接管。
- 代理/账号切换与正在运行任务的不可变绑定。
- 模型服务配置、敏感信息处理和能力调用审计；模型供应商通过端口隔离。
- 便携数据、系统加密凭据及跨机器导出的冲突处理。

## 生产验收门槛

- 用标准表单、多层列表详情、动态 SPA、登录会话、API 游标分页等不同模式验证可编排能力。
- 验证网络中断、页面超时、进程崩溃、磁盘写满、账号失效、重复请求、交付失败和升级失败；结果与恢复语义符合契约。
- 在已公布资源配置下测量成功率、延迟、内存/磁盘增长和队列积压；未经测量不写容量承诺。
- 进行至少 72 小时连续运行及发行前更长周期验证，检查文件保留、租约释放、恢复、数据一致性。长期测试不能用快速单测替代。
- 干净 Windows 环境验证运行包，移动路径验证正常，升级和备份恢复可重复执行。
- 完成中英双语、键盘可用性、1080×760 最小窗口及真实操作截图检查，无死按钮、虚构指标或覆盖页面的面板。
