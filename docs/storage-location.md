# 存储位置与迁移契约

## 使用方法

在「设置 → 存储位置」输入目标绝对路径，或点击「选择文件夹」，然后「保存目录变更」。目标必须为空（或是父目录已存在的新目录）。此时仍使用旧目录，可取消变更；退出后重新启动会复制并校验，成功才启用新目录。原目录不自动删除。

环境变量 CLAWLER_DATA_DIR 显式指定路径时，设置页显示来源并锁定目录编辑，防止界面保存的值被启动参数悄悄覆盖。移除该覆盖后，设置页可以正常配置。

如果启动迁移失败，原生错误窗口允许保留变更并退出，或取消待执行变更后退出。下一次启动仍可使用原目录。复制中断留下的暂存目录保留，用于校验与重试；取消变更不自动清除这些文件。

## 技术边界

输入：启动配置、环境覆盖、用户选择的绝对路径。输出：当前根目录、待迁移目标及配置来源。配置与离线文件迁移归属 packages/storage/location；Electron 主进程负责启动顺序、原生选目录与单实例锁。渲染层没有任意文件读写接口。

优先级：CLAWLER_DATA_DIR 显式覆盖 > 启动配置中的自定义目录 > 默认 userData。开发启动器用 CLAWLER_DEFAULT_DATA_DIR 提供旧 .cache/user-data 默认位置，用 CLAWLER_CONFIG_DIR 将启动配置放入 .cache/launcher；不再强行覆盖用户设置。发行版默认启动配置位于 appData/MimesisLauncher。

目录变更保存为 pending，允许撤销。在下一次启动 ready 前，获得源数据目录锁，检查路径不相等/不嵌套/不是符号链接、目标为空、磁盘空间充足，复制所有普通文件到受控暂存目录，逐文件 SHA-256 校验并同步，再提升为目标目录，最后原子更新启动配置。原目录永久保留，只有用户另外清理才移除。暂存标记用于崩溃重试，不递归删除任意目标目录。目标被其他文件占用、复制/校验失败、配置提交失败都不回退为一个新空工作区。

数据库/WAL、归档、浏览器分区、Local State、偏好与缓存一起迁移；仅跳过进程锁文件。sessionData 与 userData 显式绑定同一根目录并在 ready 前设置，依据 [Electron app.setPath](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path)。源目录锁只防止支持本协议的运行实例；升级前必须退出旧版本应用。

迁移失败会保留 pending 与原目录，并通过启动错误提示说明重试/撤销方法。启动时不自动删除用户数据，也不把复制失败解释为成功。该功能是同一机器上的存储路径迁移；跨机器系统凭据解密、在线备份恢复、磁盘配额及保留清理仍单独实现。

验收：76 项测试通过，包含目录关系/占用/链接检查、环境覆盖、配置写入失败、缺失自定义目录、损坏配置、空间不足、部分复制重试和提升后配置未提交的恢复。真实 Electron 通过中文路径迁移、SQLite/运行恢复、Cookie 与语言偏好保留、API 归档读取和幂等重放；设置页完成中英、Tab 焦点和 1080×760 检查。当前 Windows 本机测试未代替大目录、跨卷、干净安装和长时间运行验证。
