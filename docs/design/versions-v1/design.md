# 发布版本与回滚

先生成 versions-tab.png（built-in image_gen，提示见 prompt.md），再实现交互。复用现有 Lucide 线性图标与组件，不新增装饰素材。

## 用户任务

1. 把当前编辑的流程固化成可追溯的发布版本。
2. 看清“现在运行的是哪个版本”，而不是猜测草稿是否生效。
3. 需要时切回历史版本，且不回写正在编辑的草稿。

## 状态与操作

| 状态 | 界面 | 可执行操作 |
| --- | --- | --- |
| 无工作流 | 版本页空状态，说明先保存流程 | 无 |
| 草稿已保存、未发布 | “运行绑定”显示未发布 | 发布 |
| 已发布、草稿与绑定版本一致 | 显示版本号、发布时间、备注 | 发布（内容相同不新增版本）、运行 |
| 草稿已修改未发布 | 显示绑定版本号，并标明运行使用绑定版本 | 发布新版本后运行 |
| 发布中 | 按钮禁用，不显示虚构进度 | 无 |
| 发布失败 | 顶部错误条显示错误码文案，原绑定不变 | 重试 |
| 切换到历史版本 | 列表中标出当前版本，其余版本可切换 | 切换、运行 |
| 版本数达上限（500） | 提示达到上限，历史版本不自动清理 | 无 |

## 规则

- 发布即冻结：版本一经发布不再修改，内容相同（同一目标地址与规范化摘要）再次发布复用原版本号，不产生重复版本。
- 运行只使用绑定版本。草稿、URL 与备注在回滚时保持不变，回滚只改变“运行什么”。
- 已入队或正在执行的任务保留其被受理时的快照，回滚不改变它们的执行版本。
- 存储内容与摘要不一致时拒绝执行并报版本冲突，不回退为运行草稿。
- 运行记录保存本次执行的版本标识，历史运行可回溯到发布版本。

## 与旧行为差异

此前“保存并试跑”直接执行编辑中的草稿。现在运行绑定发布版本，未发布的草稿不会产生运行数据；发布为显式动作，`versions.publish` 与 `versions.rollback` 桌面与网关共用同一领域逻辑。
