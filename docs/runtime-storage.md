# 事务运行库

设计决策：2026-09-11。运行库归属 packages/storage，主进程只通过异步存储端口访问。数据库工作线程不依赖 Electron；浏览器资源仍只由 BrowserHost 管理。

使用 Node 自带 SQLite，避免额外 native ABI 安装依赖。DatabaseSync 的同步操作在专用 worker_threads 线程中执行，UI 与浏览器主进程不执行 SQL。依据：[Node SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。实际 Electron 兼容性以端到端测试为准。

## 数据和事务

- profiles、instances、runs、steps 分表保存；实例流程和结果等可变结构保留 JSON 列，普通标识、状态、时间和关联独立成列。
- workspace_runs 记录桌面最近运行列表；gateway_jobs 保存提交、执行快照、状态、幂等键及关联 Run，状态/创建顺序有索引。
- artifacts 保存任务产物的相对路径、字节数和 SHA-256，不将本机绝对路径持久化。
- settings 保存导入完成标记等元信息；不用整个工作区/队列作为一行 JSON。
- 启动检查数据库格式版本，未知版本、损坏库、迁移失败明确报错，不回退空库或继续旧 JSON 写入。
- 每次仓储更新独立事务；网关终态、关联 Run/Step、产物索引在同一次数据库提交。CSV/JSON 等文件先原子写入，再提交引用；未提交文件不代表任务成功。

## 旧数据迁移

数据库导入标记未设置时，读取原 workspace.json 与 runtime/gateway.json，校验并备份原文，再在一个事务中导入并设置标记。失败时原文件保留，下次启动可重试。迁移完成后 SQLite 是唯一状态源，旧 JSON 不再双写；旧文件只作为备份材料。旧格式解码仅在 migrations 层。

备份名为原路径加 `.pre-sqlite.backup.json`，已有不同内容的备份会阻止导入。已有终态归档中实际存在的文件会计算校验信息并索引；旧文件缺失时不会伪造产物记录，原始 Run 仍可通过 API 序列化输出。文件完整性巡检与缺失修复还需后续实现。

## 线程与生命周期

存储 worker 串行处理有类型的方法，拒绝未知消息。主进程不提供任意 SQL 接口。worker 出错、退出、超时后所有待处理请求明确失败，不能继续声称保存成功。关闭时先停止任务与网关、等待运行保存，再关闭数据库线程。

## 本轮边界

保留当前单执行器队列与最近 50 条桌面运行的服务契约；内存队列仍有 100/1000 容量上限。历史保留策略、清理 UI、数据库备份导出、检查点、多实例租约和 Webhook outbox 是后续功能，本轮不以引入 SQLite 代替这些能力。

仓储端口目前传输完整快照，尚未实施增量命令和数据库分页调度；分表及索引不等于吞吐量已验证。数据库保留运行行，最近 50 条只是桌面列表，不是磁盘保留策略。持续挂机前仍须完成配额与保留清理验收。
