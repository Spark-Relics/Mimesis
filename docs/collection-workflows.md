# 从录制到可复用采集

当前已实现的是可执行 JSON 流程，不是任意 JavaScript 沙盒。录制、编辑、桌面试跑和 HTTP 网关使用同一执行器。产品内没有接模型的 Agent 按钮；本轮由开发 agent 审查并修复运行层，不能把它当成产品内置的自动修复能力。

## 第一次实验

1. 新建一个实例并打开，进入“浏览与录制”。点击“打开 Quotes 实验网站”，或输入自己的 HTTP / HTTPS URL 后点击“打开网址”。
2. 如果需要登录，先在该实例的浏览器环境中手动登录。Cookie 和站点存储由持久化 Profile 保留。
3. 点击“开始录制”，在网页中按业务顺序操作。支持点击链接/按钮、普通文本输入。连续输入合并为一个 fill 步骤；密码、OTP 等识别到的敏感字段不录制。当前最多 20 个初始化步骤。
4. 在 Quotes 实验中，只点击网页的 Next，然后点击“结束并整理步骤”。录制得到 `click: li.next > a`。
5. 点击“将最后一次点击设为下一页循环”。它从初始化序列中移除，在每页提取完成后执行。录制开始时的 URL 是运行起点，不会从录制结束时的第二页开始采集。
6. 实验模板已填写：列表项 `.quote`；字段 `quote → .text → text`、`author → .author → text`；最多 2 页。所有规则都可编辑。自己的网站需要配置相应选择器。
7. “检查配置”只做 Schema 和参数检查；“保存并试跑”才真实导航、执行与验证页面。运行记录展示步骤、数据表、完整 JSON、页数及截断标记。

2026-09-09 的外部网站验收已通过：HTTPS Quotes to Scrape，真实录制 Next，回到原始 URL 执行，得到 **2 页、20 条非空 quote / author 记录**，停止原因 `page-limit`，`truncated: true`。这是前两页的结果，不是全站完成。已保存[实际流程](design/workflow-v3/quotes-workflow.json)和[工作区截图](design/workflow-v3/implemented-workflow.png)。

## Loop 如何复用

流程结构是：打开起始 URL → 初始化操作（一次）→ 提取当前页所有匹配项 → 按完整记录去重 → 判断上限和下一页 → 点击下一页 → 等待内容更新 → 回到提取。

- **初始化**：搜索关键词、点搜索、等待列表等，按序执行一次。界面支持增删、上下移动和修改选择器、输入值。
- **循环体**：每个列表项生成一条记录；字段选择器相对于该项。支持 text、href、src、value。空字段选择器表示项自身；必填字段未加载则等待。
- **继续条件**：下一页存在、可用且尚未达到上限。按钮选择器有多个匹配会失败，避免点错。
- **正常停止**：单页任务、没有下一页、换页后无新增记录。达到页数/记录/字节上限时返回数据并标记截断。
- **失败**：选择器非法、必要数据始终未出现、点击后 URL 和内容都未变化等，会得到明确失败/超时。取消和失败不返回部分采集结果，尚无断点恢复。
- **限制**：最多 50 页、2000 条记录、约 2 MB 字段数据；每步等待 100–15000 ms；整次采集最多 120 秒。这里只支持一层翻页循环，尚无“列表 → 详情 → 返回列表”的嵌套子流程。

例如，把录制的搜索输入值改为 `{{keyword}}`。桌面“本次运行参数”填 `{"keyword":"books"}`；下次换成另一个值，即可复用同一操作规则。输入内容按字面值传给浏览器，不作为代码执行。参数缺失时在导航前拒绝。参数值不会成为桌面默认配置，但网关任务快照会保存本次参数，因此不要把密码或令牌作为普通采集参数。

## 从项目请求

按[网关启动说明](gateway.md)启动带 Token 的本机服务，使用配置页显示的实际实例 UUID：

```json
{
  "instanceId": "<实例 UUID>",
  "parameters": { "keyword": "books" }
}
```

携带 Bearer Token 向 `POST http://127.0.0.1:17840/v1/jobs` 提交。轮询 `GET /v1/jobs/:id` 到终态，再取 `GET /v1/jobs/:id/result?format=csv`（也支持 json、ndjson）。Quotes 示例没有输入占位符，可以省略 parameters。

提交时保存流程、Profile、起始 URL、参数和脚本版本快照。排队期间修改流程不会改写已接受任务。JSON 的 `records` 是字段数据，`collection` 是页数/停止原因/截断信息；CSV 按字段成列，NDJSON 每行一条记录。调用方应检查截断信息，不能仅凭 succeeded 判断全站采集完成。

本地端到端测试还验证了：录制搜索和翻页、排除密码、将输入变为参数模板、桌面参数 beta 得到 4 条对应数据，再通过 API 参数 gamma 复用流程并导出三种格式。正常重启、Profile 隔离与网关恢复由独立 Electron 用例验证。

## 目前仍需明确的边界

自动生成的选择器需要试跑确认；动态 class、iframe、Shadow DOM、下拉选项、上传、键盘快捷键和无限滚动不在本轮录制能力中。手动登录依赖保存的浏览器会话。任意网站适配、页面请求/响应捕获、账号轮换、代理、机器环境隔离、调度保留策略、运行中 Agent 修复仍未实现。

普通开发检查使用 `pnpm check` 与 `pnpm test:e2e`。外网实验默认跳过，明确运行：

```powershell
$env:CLAWLER_LIVE_TEST = '1'
pnpm test:e2e tests/electron/live-collection.spec.ts
```
